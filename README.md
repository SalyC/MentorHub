# MentorHub

Образовательная платформа для менторства — информационная система для организации учебного процесса между учениками и менторами.


---

## О проекте

MentorHub — это веб-приложение, в котором:
- **Ученики** записываются на курсы, изучают материалы, сдают задания и получают оценки.
- **Менторы** создают курсы, добавляют уроки и задания, проверяют работы и общаются с учениками в чате.
- **Администраторы** управляют пользователями, курсами и ролями.

Система построена на микросервисной архитектуре с асинхронной обработкой событий через Kafka, кэшированием в Redis и уведомлениями в Telegram.

---

## Возможности

### Для ученика
- Регистрация и вход (JWT-аутентификация)
- Просмотр доступных курсов и запись на них
- Изучение материалов курса (текст, файлы, ссылки)
- Отправка решений заданий с учётом дедлайнов
- Просмотр оценок и комментариев ментора
- Участие в чате курса в реальном времени (WebSocket)
- Уведомления внутри системы и в Telegram

### Для ментора
- Всё, что доступно ученику
- Создание и редактирование собственных курсов
- Добавление модулей, материалов и заданий
- Проверка решений, выставление оценок
- Объявления для учеников курса

### Для администратора
- Управление пользователями (создание, блокировка, смена роли)
- Управление курсами и назначение менторов
- Просмотр статистики платформы

## Стек технологий

### Frontend
- **React 18** + **TypeScript**
- **Vite** — сборка и dev-сервер
- **Tailwind CSS** + **shadcn/ui** — стилизация
- **TanStack Query** — работа с API
- **Zustand** — глобальное состояние
- **React Router** — маршрутизация
- **WebSocket** — чат в реальном времени

### Backend
- **Go 1.22+** — язык разработки
- **chi** — HTTP-роутер
- **pgx** + **sqlx** — работа с PostgreSQL
- **go-redis** — клиент Redis
- **kafka-go** — клиент Kafka
- **zerolog** — структурированное логирование
- **JWT** — аутентификация

### Инфраструктура
- **PostgreSQL 16** — основная БД
- **Redis 7** — кэш, сессии, pub/sub
- **Apache Kafka** (KRaft) — брокер сообщений
- **Docker Compose** — локальная разработка

## Архитектура

Проект построен по принципам микросервисной архитектуры.

### Сервисы
| Сервис | Назначение |
|---|---|
| **API Gateway** | Единая точка входа, маршрутизация, проверка JWT |
| **Auth Service** | Регистрация, аутентификация, управление пользователями |
| **Course Service** | CRUD курсов, модулей, материалов, заданий |
| **Grade Service** | Сдача решений, проверка, оценки |
| **Chat Service** | WebSocket-чат, публикация событий |
| **Notification Service** | Обработка событий Kafka, отправка уведомлений в Telegram |

### Взаимодействие
- Синхронные запросы — через **REST** (маршрутизируются Gateway).
- Асинхронные события — через **Kafka**.
- Кэш и обмен сообщениями между экземплярами — через **Redis**.

### Основные события Kafka
| Топик | Описание |
|---|---|
| `user.registered` | Новый пользователь зарегистрирован |
| `user.role_changed` | Роль пользователя изменена |
| `course.created` | Создан новый курс |
| `assignment.created` | Создано задание |
| `submission.submitted` | Ученик отправил решение |
| `submission.graded` | Ментор выставил оценку |
| `chat.message` | Новое сообщение в чате |
| `deadline.reminder` | Напоминание о дедлайне |

## Быстрый старт

### Требования
- **Node.js** 20+
- **Go** 1.22+
- **Docker Desktop** с Docker Compose

### 1. Клонирование

```bash
git clone https://github.com/SalyC/MentorHub.git
cd MentorHub
```

### 2. Запуск инфраструктуры

```bash
cd backend
docker compose up -d
```

Поднимутся PostgreSQL, Redis, Kafka и Kafka UI:
- PostgreSQL: `localhost:5432`
- Redis: `localhost:6379`
- Kafka: `localhost:9094`
- Kafka UI: http://localhost:9000

### 3. Настройка бэкенда

```bash
cd backend
cp .env.example .env
# При необходимости отредактируй .env
go mod download
go run ./cmd/healthcheck
```

`healthcheck` подключается ко всем сервисам и печатает статус конфигурации.

### 4. Запуск фронтенда

В новом терминале, из корня проекта:

```bash
npm install
npm run dev
```

Фронтенд будет доступен на http://localhost:5173

## Разработка

### Ветки

- **`main`** — стабильная версия, защищена от прямых пушей
- **`develop`** — основная ветка разработки
- **`feat/*`** — по одной на каждый модуль/сервис
- **`chore/*`** — рутина (конфиги, зависимости)
- **`docs/*`** — документация

### Процесс

1. Создать ветку от `develop`
2. Сделать изменения, закоммитить
3. Открыть Pull Request в `develop`
4. После ревью — squash and merge

### Соглашение о коммитах

Используется [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` — новая функциональность
- `fix:` — исправление бага
- `chore:` — рутина
- `docs:` — документация
- `refactor:` — рефакторинг
- `test:` — тесты
